| **Tags** | `API`, `Data Wake`, `Storefront`, `integração`, `Biso`, `dados` |

**Problema:** Durante a integração técnica Biso + Wake, havia dúvida sobre qual API usar para exportação e cruzamento de dados de produtos e vendas.

**Decisão técnica documentada:**
- **Data Wake foi descartado** para este uso. Ele deve ser utilizado apenas para consultas em tempo real
- **Motivo:** A Biso precisa salvar dados em seus servidores para cruzar com outras fontes (mídia, marketplaces, logística) — isso não é compatível com o modelo do Data Wake
- **Solução definida:** Usar **API Pública + API Storefront**

**Query de referência (GraphQL — API Storefront) para obter categorias de produtos:**
```graphql
query Category {
  products(filters: {productVariantId: XXXXX, ignoreDisplayRules:true}, first: 50) {
    nodes {
      productCategories {
        active
        googleCategories
        hierarchy
        id
        main
        name
        url
      }
    }
  }
}
```

**Vantagem:** Por ser uma query de `products`, múltiplos outros campos de dados do produto podem ser retornados na mesma chamada, potencialmente substituindo chamadas à API Pública.

**Problemas identificados no processo de assinatura:**

1. **Proposta comercial não anexada:** O jurídico Wake bloqueou as assinaturas pois o parceiro não havia anexado a proposta comercial no envelope digital. Resolução: incluir a proposta no envelope antes de liberar para assinaturas.

2. **Contrato com comentários e versões antigas:** O documento circulou com muitos comentários de edições anteriores. Solução: solicitar ao jurídico uma **versão limpa** do contrato antes de iniciar o processo de assinaturas.

3. **Plano incorreto no contrato:** O contrato foi enviado com dados do plano anterior (Special quando deveria ser Essential, ou vice-versa). Resolução: verificar nas cláusulas 5.4 e 3.2.1 se o plano e o valor do partner fee estão corretos antes de assinar.

**Sequência correta do processo:**
1. Acordo comercial documentado por e-mail
2. Jurídico Wake emite versão limpa do contrato com plano correto
3. Parceiro revisa e confirma dados
4. Parceiro sobe contrato + proposta comercial no envelope digital
5. Assinaturas na ordem acordada
6. Wake jurídico assina por último

**Processo para publicação de banner promocional no admin Wake:**

1. **Arte:** A Wake (time de design) é responsável pela produção final do banner. O parceiro fornece apenas o **media kit da marca**
2. **Limite de caracteres:** Máximo de **600 caracteres** para a descrição
3. **CTA obrigatório:** O banner deve ter QR code ou link para contato (ex: WhatsApp do time comercial do parceiro)
4. **Duração:** Banners ficam no ar por **1 a 2 semanas**
5. **Agendamento:** É possível pré-agendar uma data futura (ex: aguardar abertura para base full antes de publicar)
6. **Conteúdo de exemplo (Appmax):**
   - Título: *"Máxima performance em pagamentos online com pix 100% gratuito"*
   - Texto: destaca 99% de aprovação, antifraude com IA, PIX sem taxa
   - CTA: *"Quero migrar pra Appmax!"* com link para WhatsApp
